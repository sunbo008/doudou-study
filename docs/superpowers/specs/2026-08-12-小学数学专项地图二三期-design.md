## 1. 背景与目标

一期已建立 14 个专项、双视图索引、统一知识点模板和 4 个厚实样板。二、三期不改变一期架构，而是在同一结构中把占位清单扩展为可独立学习、检索和测评的细知识点正文。

本期成功标准：

- 二期覆盖六年级上、下册正式目录中的全部数学单元，并补充分班高频内容；
- 三期按同一粒度覆盖一年级至五年级，不以整单元巨型文件代替细知识点；
- 六年级教材单元以用户提供的实书目录为准；一至五年级先按可靠公开目录建设并标记核验状态；
- 每个 active 知识点至少包含 L1、L2；核心及分班高频知识点补齐 L3、L4；
- 双视图、专项 README、知识正文和练习回链一致，无重复 ID、断链或漏索引；
- 新增只读校验脚本，自动执行结构与覆盖检查。

## 3. 范围与内容粒度

### 3.1 二期

- 按六年级上、下册逐单元拆分细知识点并填厚；
- 单独覆盖综合实践与数学广角；
- “总复习”“整理和复习”只建立聚合导航，不复制已有知识正文；
- 补充分班高频的分数、百分数、比与比例、圆、圆柱圆锥、方程和典型数量关系；
- 为 14 个专项补充适龄的 L4 横向题或明确的跨专项引用。

### 3.2 三期

- 一至五年级逐册、逐单元回填细知识点；
- 对照可靠公开目录填写 `pep_units`，统一标为公开目录已核验；
- 对核心知识点补齐 L3、L4，对基础条目补齐 L1、L2；
- 后续取得实书目录时，批量复核册次和单元名称。

### 3.3 拆分规则

一个 `kp_*.md` 只承载一个可独立教学与测评的能力。例如“分数乘法”至少拆为意义、计算、混合运算、解决问题等，不写成一个覆盖整单元的巨型文件。

满足以下任一条件时应拆分：

- 学习目标不同；
- 解题决策或核心算法不同；
- 易错点和自检方法不同；
- 可独立出题与复测；
- 教材中形成独立小节或分班考试中形成独立题型。

同一知识只维护一个正文。跨专项内容确定一个主专项，其他位置只链接引用。

## 4. 架构与组件

### 4.1 正文与导航

- `docs/小学数学地图/specialties/Sxx-*/kp_*.md`：知识正文唯一来源；
- `specialties/Sxx-*/README.md`：专项范围及知识点清单；
- `专项索引.md`：按能力专项导航；
- `年级索引.md`：按年级、册次、教材单元导航；
- `_meta/人教版对齐说明.md`：版本、核验口径和差异记录；
- 校验脚本：只读检查，不生成或改写正文。

不引入数据库或中央 YAML 清单，也不自动生成双视图。Markdown 正文仍为唯一事实来源。

### 4.2 Frontmatter 扩展

在一期字段基础上新增：

```yaml
source_verification: verified_book  # verified_book | verified_public | pending
```

含义：

- `verified_book`：已由用户提供的实书目录核验；
- `verified_public`：已由可靠公开目录核验，尚未与手边实书比对；
- `pending`：暂缺可靠目录，仅能保留占位，不得发布为 active。

六年级教材内条目使用 `verified_book`。一至五年级在公开来源核验完成后使用 `verified_public`。

## 5. 知识点正文契约

每个细知识点继续遵守一期模板：

1. 一句话目标；
2. L1～L4 典型题型表；
3. 与实际难度档对应的例题；
4. 常见坑与易混；
5. 年级与单元；
6. 思维横向题；
7. 关联知识、练习和弱项。

每道实际写出的例题必须包含：题目、难度、解题技巧、步骤要点、避坑思路、答案。

难度规则：

- active 条目必须有 L1、L2；
- 核心知识点和分班高频知识点必须有 L3、L4；
- 低年级基础条目若不适合独立设置 L4，可标“暂不设置”，但须说明适龄原因，并链接其横向能力去向；
- 跨专项 L4 只维护一份正文，引用条目必须提供有效链接；
- 禁止为凑难度生造超出小学认知范围或依赖未学符号体系的题目。

## 6. 数据流与维护流程

```text
教材目录
  → 年级 / 册次 / 单元
  → 细知识点拆分
  → 主专项归属
  → kp 正文
  → 专项 README
  → 专项索引 + 年级索引
  → 练习与弱项回链
  → 自动校验
```

维护顺序固定为：先确认教材归属，再创建正文，然后更新专项 README 和双视图，最后运行全量校验。不得先在索引中发布尚不存在的 active 文件。

## 7. 校验设计

新增仓库内只读校验脚本，至少检查：

- `kp_id` 与文件名主干一致，且全局唯一；
- `specialty_id`、`grades`、`pep_units`、`status`、`source_verification` 合法；
- `pending` 条目不能标为 active；
- active 条目至少存在 L1、L2；
- 每道例题具有六个强制子块；
- 声明的 L3、L4 有对应例题或有效跨条目链接；
- 专项 README、专项索引、年级索引中的 Markdown 链接均可解析；
- 每个 active 文件均被专项清单和双视图覆盖；
- 同一 `kp_id`、同一正文或同一稳定知识点没有重复维护；
- 六年级实书目录和一至五年级公开目录均有覆盖记录。

脚本失败时输出文件路径、规则名称和可定位的问题描述，并以非零状态退出。

## 8. 异常与版本差异处理

- 无可靠目录证据：使用 `pending`，不猜测、不发布 active；
- 公开目录与实书不同：实书优先，差异写入对齐说明；
- 单元归属变化：调整 `pep_units`，不修改 `kp_id`；
- 同一知识跨多个单元：正文保留一份，在 `pep_units` 中列出多个归属；
- 一期索引或元数据错误：直接修正单元名、册次和链接，但保持稳定 ID；
- 例题答案无法可靠复核：条目保持 draft，不能进入 active 索引；
- 低年级无合理 L4：写明“暂不设置”的原因并链接适龄横向能力，不硬凑竞赛题。

## 9. 验收

### 9.1 结构验收

- 校验脚本全量通过；
- 无重复 ID、断链、漏索引和非法状态；
- Markdown 正文仍为唯一知识数据源。

### 9.2 内容验收

- 每个专项至少抽查一个 active 条目；
- 抽查例题独立重算，答案正确；
- 解题技巧可迁移，避坑思路针对本题且可执行；
- L4 符合“先识别结构或转化，再运算”的定义。

### 9.3 覆盖验收

- 六年级实书正式目录全部映射，综合实践与数学广角不遗漏；
- 一至五年级可靠公开目录全部映射；
- 二期、三期完成状态及尚待实书复核项有独立汇总；
- 双视图可从教材单元和专项两个方向到达同一知识正文。

## 10. 分期实施顺序

1. 建立教材目录清单和校验器的失败测试；
2. 修正一期六年级索引与元数据；
3. 完成六上细知识点；
4. 完成六下细知识点；
5. 补充分班高频及 14 专项 L4；
6. 全量验收二期；
7. 核验一至五年级公开目录；
8. 逐年级回填细知识点；
9. 查漏补 L3、L4，并完成三期全量验收。

## 11. 非目标

- 不自动生成练习卷；
- 不引入题库数据库；
- 不复制教材原文或整页习题；
- 不改造 AI 答辩式学习系统；
- 不因目录文本调整而重命名稳定 ID；
- 不把“公开目录已核验”表述为“用户实书已核验”。

## 12. 已确认决策

1. 二、三期均采用细知识点拆分；
2. 六年级以用户提供的 2022 审定版实书目录为准；
3. 一至五年级先按可靠公开目录开发，待实书复核；
4. 采用 Markdown 唯一数据源加轻量只读校验脚本；
5. 保持一期双视图与 14 专项架构；
6. 核心及分班高频补齐 L3、L4，低年级不强行生造不适龄 L4；
7. 实现顺序为先二期、验收后再三期。
